# Roadmap проекта

Архитектурная миграция портфолио на **Next.js (App Router)**, **Feature-Sliced Design (FSD)** и **next-intl** успешно завершена.

Все этапы миграции (0–5), включая перенос стилей, локальных шрифтов, темного/светлого оформления, локализации, анимаций, серверной модели данных и верификацию 233 эталонных снимков экрана без визуальных регрессий, выполнены и задокументированы:
- [История миграции](docs/migration/history.md) — детальная хронология и состав выполненных работ по этапам.
- [Архитектурные решения (ADR)](docs/migration/decisions.md) — ключевые решения по стеку, FSD, i18n, управлению темой и изоляции серверных данных.
- [Отчёт о верификации](docs/migration/verification.md) — результаты модульных, архитектурных, дымовых (Chromium/Firefox) и визуальных тестов.

## Архитектурный базис проекта

Приложение выстроено по методологии FSD со строгой иерархией слоёв и серверным runtime Next.js:

```text
proxy.ts                          # Middleware локализации next-intl
app/                              # Маршруты и страницы Next.js App Router
  [locale]/
    layout.tsx
    page.tsx
    error.tsx
    not-found.tsx
    [...rest]/page.tsx
    project/[id]/page.tsx
    project/loading.tsx
src/
  _app/                           # Провайдеры, инициализация темы, i18n, метаданные
  _pages/                         # Композиция страниц (home, project, not-found)
  widgets/                        # Крупные блоки (header, hero, services, projects, contact, footer)
  features/                       # Сценарии пользователя (switch-language, switch-theme)
  entities/                       # Сущность project (модель, UI и серверный index.server.ts)
  shared/                         # UI-компоненты, SCSS-стили, ассеты, адаптеры навигации i18n
messages/                         # Словари переводов en, ru, uz (ICU)
public/                           # Статические файлы (favicon, manifest, OG-изображения)
```

Правила архитектуры и границы импортов проверяются автоматически с помощью `eslint-plugin-boundaries` и набора тестов `pnpm test:architecture`.

## Планы развития (Бэклог)

### 1. Подключение внешнего источника данных (GitHub / BaaS / CMS)
Интерфейс получения данных проектов уже вынесен в изолированный серверный модуль `src/entities/project/index.server.ts` (`getProjects` / `getProject`), что позволяет подключить внешний провайдер без изменения UI-компонентов и страниц.

- [ ] Выбрать целевой источник данных:
  - **GitHub Content API / репозиторий:** хранение контента проектов в JSON/MDX в Git.
  - **BaaS (Supabase / Appwrite):** база данных с панелью управления.
  - **Headless CMS (Sanity / Strapi):** удобный интерфейс редактирования контента.
- [ ] Реализовать серверный адаптер источника данных с реализацией интерфейса `getProjects` и `getProject`.
- [ ] Настроить валидацию схемы получаемых данных (например, Zod) и маппинг во внутреннюю модель `Project`.
- [ ] Настроить стратегию серверного кэширования и инвалидации (Next.js `revalidateTag` / ISR), исключая избыточные запросы к внешнему API при повторных просмотрах.
- [ ] Реализовать gracefully degrading fallback при недоступности внешнего сервиса или исчерпании лимитов API.
