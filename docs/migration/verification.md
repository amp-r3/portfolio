## Особенности окружения проверки

Для серверов, браузеров и дочерних процессов сборки использовался запуск вне ограниченной песочницы. Внутри неё build не смог прочитать вывод дочернего TypeScript, а browser preview не запустился; это ограничения среды, а не исключения из проверок приложения.

Системная установка библиотек Firefox/WebKit через `playwright install-deps` потребовала недоступного sudo-пароля. Для проверки библиотеки Ubuntu были скачаны через `apt-get download` и распакованы в `$HOME/.cache/portfolio-playwright-libs`, без изменения установленных системных пакетов. Firefox запускался с `LD_LIBRARY_PATH`; WebKit — через временную обёртку `$HOME/.cache/portfolio-webkit.sh` и временную конфигурацию, поскольку штатный `MiniBrowser` перезаписывает `LD_LIBRARY_PATH`. Использовались исходные скачанные бинарные файлы Playwright. Для Chromium и Firefox ни один тест не пропускался. WebKit проходит отдельный тест, но полный набор в этой среде зависает на `page.reload()`; ограничение вынесено в отчёт этапа 3 и не маскируется пропуском теста.

На обычной машине для воспроизведения достаточно установить системные зависимости штатной командой из README и выполнить `pnpm test:smoke`; тогда WebKit также проверяется.

Визуальные проверки выполняются последовательно, без одновременной сборки Next.js: параллельные тяжёлые процессы в этой среде вызывали нехватку памяти и таймауты. Для PNG используется Chromium Headless Shell 156.0.8078.4 из закреплённого Playwright 1.64.1. Перед сравниваемым кадром выполняется прогревающий снимок, чтобы завершилась отрисовка слоёв с `filter`/`backdrop-filter`. Допуск ограничен субпиксельным шумом (канал ≤3, ≤600 значимых пикселей, крайняя строка/столбец); `tests/visual/baseline` не перезаписывался.
