# История миграции портфолио на Next.js и FSD

В этом документе зафиксирована детальная хронология, содержание работ и результаты верификации архитектурной миграции проекта с Vite, React Router и i18next на Next.js (App Router), Feature-Sliced Design (FSD) и next-intl.

---

## 1. Цели, ограничения и приоритеты

### Исходное состояние
- **Фреймворк и сборка:** React 19, TypeScript, Vite, pnpm.
- **Маршрутизация:** React Router v7 (`/`, `/project/:id`, 404).
- **Интернационализация:** `react-i18next` с JSON-файлами в `public/locales/{en,ru,uz}/`. Локаль не сохранялась в URL и сбрасывалась при обновлении страницы.
- **Стили и тема:** SCSS Modules, глобальные токены в `src/styles/`, переключение темы через `data-theme` на `<html>` с fallback на dark в `localStorage`.
- **Данные:** статический файл `src/data/projectsData.ts` импортировался напрямую в клиентские компоненты.
- **Развёртывание:** SPA-правило Netlify (`public/_redirects`).

### Главный критерий миграции
**100% визуальное и поведенческое соответствие исходной версии.**
Сохранены:
- Композиция страниц, тексты, изображения, локальные шрифты (Inter, Exo2, Azonix).
- Размеры, отступы, цветовая палитра токенов, адаптивные брейкпоинты.
- Светлая и тёмная темы (включая выбор тёмной темы по умолчанию).
- Состояния элементов (hover, focus, active, scrolled).
- Характер и динамика анимаций (Motion, Locomotive Scroll, marquee).

## 2. Хронология этапов

### Этап 0. Зафиксировать визуальный и функциональный эталон (Baseline)
**Цель:** создать воспроизводимый эталон исходной версии до внесения любых изменений в кодовую базу.

- **Фиксация коммита:** исходный коммит `1ba5927996ee783577c6d6c38ad69796f6afea4c`, Node.js `24.15.0`, pnpm `10.33.3` ([baseline.json](baseline.json)).
- **Detached worktree:** настроен запуск эталонного приложения в `.worktrees/portfolio-baseline` на порту 4173 независимо от основного репозитория.
- **Съёмка эталона:** Playwright зафиксировал 233 эталонных PNG-скриншота (`tests/visual/baseline/`):
  - 5 маршрутов (главная в 5 секциях, Weather, Store, неизвестный проект, 404).
  - 3 языка (`en`, `ru`, `uz`).
  - 2 темы (`light`, `dark`).
  - 3 вьюпорта (375×812, 768×1024, 1440×900).
  - Пограничные брейкпоинты и интерактивные состояния (hover, focus, меню, прокрученный хедер).
- **Видеозаписи:** записаны видео сессий скролла, переключения тем и открытия меню на desktop и mobile.
- **Каталог дефектов исходной версии:** зафиксированы особенности исходного поведения (отсутствие языка в URL, SPA-ответ HTTP 200 на 404, лишняя скобка в `mailto:`, селекторы градиентных слоёв), чтобы отличать их от регрессий.

### Этап 1. Создать каркас Next.js и границы FSD
**Цель:** развернуть фундамент Next.js App Router и архитектуру FSD с автоматическим контролем границ.

- **Стек:** Next.js 16.4.2, React 19.3.1, TypeScript 5.9.3, Sass 1.94.2.
- **Слои FSD:** создана структура:
  - `src/_app/` — корневая инициализация, провайдеры, i18n, метаданные.
  - `src/_pages/` — композиция страниц.
  - `src/widgets/` — самостоятельные блоки интерфейса.
  - `src/features/` — сценарии взаимодействия пользователя.
  - `src/entities/` — предметные сущности.
  - `src/shared/` — переиспользуемый инфраструктурный код.
  - `app/` — адаптер маршрутов Next.js App Router.
- **Контроль архитектуры:**
  - Настроен `eslint-plugin-boundaries` для контроля направлений импорта (`_app → _pages → widgets → features → entities → shared`) и публичных API слайсов.
  - Написан тест `tests/architecture.test.mjs` (12 сценариев).
- **Маршруты:** настроены базовые точки входа для главной страницы и `/project/[id]`.

### Этап 2. Перенести стили, ресурсы и тему
**Цель:** перенести глобальные стили, шрифты, медиа-ресурсы и обеспечить бесконфликтную гидратацию темы.

- **Стилизация:** все SCSS-переменные, миксины, reset и глобальные стили перенесены в `src/shared/styles/` с сохранением селекторов и структуры специфичности CSS.
- **Шрифты:** шрифты Inter, Exo2 и Azonix перенесены в `src/shared/assets/fonts/` с сохранением `@font-face` определений. Проверена их загрузка через Font Loading API.
- **Ассеты:** растровые и векторные ресурсы перенесены в `src/shared/assets/` с адаптацией путей для Next.js.
- **Управление темой без FOUC:**
  - Реализован инлайн-скрипт `ThemeScript`, применяющий атрибут `data-theme` на тег `<html>` до парсинга страницы.
  - Создан `ThemeProvider` на базе `useSyncExternalStore` без каскадных ререндеров и рассинхронизации гидратации.
  - Реализован компонент `ThemeSwitch` в слое `features/switch-theme`.
- **Smoke-тесты:** проверены холодный старт с сохранённой темой, дефолтная темная тема при любой системной теме и работа при заблокированном `localStorage`.

### Этап 3. Подключить next-intl и перенести интерфейс
**Цель:** перенести всю разметку, анимации и многоязычность на Next.js App Router с проверкой против визуального эталона.

- **Маршрутизация `next-intl`:**
  - Конфигурация: `localePrefix: 'always'`, `defaultLocale: 'en'`, `localeDetection: false`.
  - Маршруты: `/en`, `/ru`, `/uz` и `/{locale}/project/{id}`.
  - Редиректы со старых путей (`/` → `/en`, `/project/:id` → `/en/project/:id`) с кодами 307/308 и сохранением query-параметров.
  - Подключение middleware через `proxy.ts`.
- **Словари и форматирование:**
  - Перенесены переводы `en.json`, `ru.json`, `uz.json` в каталог `messages/`.
  - Форматирование адаптировано под ICU (замена `<0>` на rich text тег `<code>` для страницы 404, сохранение литеральных фигурных скобок `{ ids, items }`).
  - Создан `tests/messages.test.mjs` (7 проверок).
- **Перенос UI-компонентов:**
  - Перенесены виджеты: `Header`, `HeroSection`, `SkillsSection`, `ProjectsSection`, `ContactSection`, `Footer`.
  - Перенесены страницы: `home`, `project`, `not-found`.
  - Header помещён в общий `layout`, а Footer вынесен строго на главную страницу.
  - Сохранены анимации Motion, Locomotive Scroll и бегущие строки навыков (marquee).
- **Визуальная верификация (Candidate):**
  - Запущен регрессионный прогон `VISUAL_TARGET=candidate pnpm test:visual`.
  - 141 сценарий сравнения с baseline (233 эталонных снимка) пройден с результатом 0 расхождений.
  - Пройдены smoke-тесты в Chromium и Firefox (32 проверки).

### Этап 4. Ввести серверный доступ к текущим данным
**Цель:** вынести логику получения проектов в серверный слой с защитой от клиентских импортов и Server Components.

- **Модель данных:**
  - Выделены строгие интерфейсы `Project`, `ProjectBenefit`, `ProjectLinks`, `ProjectImages` в `src/entities/project/model/types.ts`.
  - Исходные статические данные проектов изолированы в `src/entities/project/model/raw-projects.ts`.
- **Серверный API:**
  - Реализованы функции `getProjects(locale)` и `getProject(id, locale)` в `src/entities/project/api/get-projects.ts`.
  - Добавлена защита `import 'server-only'`.
  - Введена типизированная ошибка `ProjectSourceError`. Неизвестный идентификатор возвращает `null` (ведёт к 404), а ошибка данных направляется в `error.tsx`.
- **Разделение интерфейсов:**
  - Клиентский barrel `src/entities/project/index.ts` отдаёт только типы и UI (`ProjectCard`, `BenefitCard`).
  - Серверный barrel `src/entities/project/index.server.ts` отдаёт функции доступа и защищён `server-only`.
- **Server Components:**
  - Страницы `HomePage` и `ProjectPage` получают данные на сервере и передают сериализуемые пропсы в клиентские виджеты без клиентских HTTP-запросов.
- **Тесты:**
  - Добавлен `tests/projects.test.mjs` (6 тестов изоляции и данных).
  - Расширены архитектурные тесты до 14 проверок.

### Дополнительное улучшение: переключение языка на 404
- **Проблема:** при смене языка на странице 404 (`/en/unknown-url`) запрос к серверному ресурсу через RSC вызывал сбой и вспышку темы.
- **Решение:** в коммите `df4feea` переключатель языков адаптирован для корректного перехода на локализованную страницу 404 без серверных конфликтов и сбоев гидратации темы.
